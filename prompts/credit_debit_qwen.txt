## DOCUMENT CONTEXT
A Sales Return Credit Note is issued by a seller when a buyer returns goods or when a
price adjustment is made in the buyer's favour. It partially or fully reverses an original
sales invoice. Key characteristics:
- Always references one or more original voucher / invoice numbers.
- The returning party appears under Billing Details or similar headers.
- Commonly generated by billing software (e.g., mazu.in, Tally ERP) — expect section
  headers like "Billing Details", "Shipping Details", "Transporter Details".
- Contains Seller info, Credit Note header, Transport Details, Billing Details,
  Shipping Details, Line Items, Other Charges, Tax Summary, Sundry Details, and a
  Footer.


## GENERAL RULES
Extract values EXACTLY as they appear in the OCR. Do not calculate, infer, or fill gaps
from context.
null  = the field does not exist anywhere on this document.
0     = the field exists on the document but the value is missing, unreadable, or ambiguous.
Exception: 'item_description' must always be a best-effort guess — never null or 0.

WORKED EXAMPLES ARE ILLUSTRATIVE ONLY
Any sample values shown inside a WORKED EXAMPLE block (item names, quantities, prices,
tax rates, HSN codes, dates, addresses, etc.) are placeholders to illustrate a pattern
or rule. They are NEVER the answer for the actual document you are processing. Always
extract the real values from the OCR text in front of you, regardless of what numbers
appear in any example in this prompt.

## LINE ITEM RULES

### COLUMN HEADER IDENTIFICATION — READ THIS FIRST
Before extracting any line item data, identify the column headers printed at the
top of the item table. Match each header to its canonical key using the synonym
lists below (e.g. a header "Qty" / "Quantity" / "Nos." maps to 'quantity';
"Rate" / "Unit Price" / "Price" maps to 'unit_price'; "HSN/SAC code" / "HSN Code"
maps to 'hsn_sac').

Whatever order the document prints columns in is the order that applies. There is
no fixed canonical order — different templates put columns in different sequences
(HSN may come before Qty or after, Tax % may come before Disc or after, columns
may be missing entirely). Map by header text, not by position number.

Once headers are identified, hold that mapping for the ENTIRE table across ALL
pages. For every line item row, extract each cell into the canonical key that the
column's header names.

The Sr. (serial number) column and the HSN/SAC column are two different columns.
Values from the Sr. column are NEVER HSN codes. Values from the Qty column are
NEVER HSN codes. A cell is only a valid HSN/SAC value if it appears under the
HSN/SAC header for that row. If the HSN/SAC cell is empty for a row, set 'hsn_sac'
to null for that item — do not substitute from any other column, and do not zero
out any other column either.


### Column name synonyms — map to canonical keys:

'sno'
Synonyms: S.No., Sr., Sr. No., #, Sl. No., Item No., No.

'item_description'
Synonyms: Item Description, Item, Item Name, Product, Particulars, Description,
          Product Name, Goods, Name of Item, Material, Article, Stock Item.
This field must ALWAYS have a best-effort value. Never null or empty.
If truly unreadable, use "Unknown Item".

DESCRIPTION RULE: 'item_description' is always the primary item label only — clean
product name / code. Numeric values belong to the numeric columns (Qty, Unit Price,
Amount) of the same row, and unit-of-measure tokens belong to the Unit column —
each identified by its header. They never belong to 'item_description', regardless
of where they sit in the row. Apply the CONTINUATION rule strictly — merge any
trailing description-only rows into the previous item's 'description_detailed'
field.

'description_detailed'
Additional sub-description appearing as a SEPARATE ROW below the item name row,
where that separate row has NO values in any numeric column (quantity, unit_price,
amount) whatsoever.
Synonyms: Item Details, Description (when in a sub-row), Batch No., Batch, Godown,
          Godown Name, Location, Tracking No., Serial No., Lot No., Expiry Date.

CONTINUATION RULE (strict): A row qualifies as a continuation row ONLY if:
  (a) It contains text in the item_description / description column, AND
  (b) ALL of quantity, unit_price, and amount columns are completely empty for
      that row.
If both conditions are met, append its text to the current item's
'description_detailed' field using a space separator. Do NOT create a new line item
object. If 'description_detailed' would contain only an HSN code or a quantity+unit
string, set 'description_detailed' to null instead.

'account'
Synonyms: Account, Ledger, Account Head, Ledger Account, GL Account, Sales Account.
Not always present. Null if not found.

'hsn_sac'
Synonyms: HSN, SAC, HSN/SAC, HSN/SAC code, HSN Code, SAC Code, Tariff Code, Chapter Code.
Always a STRING to preserve leading zeros. e.g. '05' not 5, '09011010' not 9011010.
Extract ONLY from the cell under the HSN/SAC header. If that cell is blank or
absent for a given row, set 'hsn_sac' to null. NEVER pull a value from the
quantity, sno, unit, or item_description column into 'hsn_sac'. A quantity value
like "11.00" or "3.00" is never an HSN code. A serial number is never an HSN code.

WORKED EXAMPLE — blank HSN cell (ILLUSTRATIVE — concept, not a fixed layout):
Suppose a line item row contains:
  - a value under the Item Description header            -> <ItemName>
  - a BLANK cell under the HSN/SAC header                -> (empty)
  - a numeric value under the Qty header                 -> <QtyVal>
  - normal values under the remaining headers (Unit,
    Unit Price, Disc, Tax %, Amount, etc.)               -> as printed

CORRECT extraction:
  'item_description' = "<ItemName>"
  'hsn_sac'          = null            (the HSN cell was blank)
  'quantity'         = <QtyVal>        (Qty value stays in the qty key)
  every other field is the value from the cell under that field's own header.

WRONG — do NOT do this:
  'hsn_sac' = "<QtyVal>"   (qty value pushed into hsn_sac)
  'quantity' = 0           (qty column emptied to fill hsn_sac)

A blank HSN cell means 'hsn_sac' = null AND the quantity value stays in the
quantity field. The blank HSN cell does NOT change any other column. Each column's
value comes only from its own cell, identified by the column's header text — never
substitute a value from one column into another column.

### ITEM TABLE BOUNDARY DETECTION

NEW LINE ITEM signals (require MULTIPLE columns simultaneously):
PRIMARY: A new numeric value appears in the quantity column AND a new numeric value
appears in the unit_price or amount column in the same row.
SECONDARY: A new item name appears in the item_description column alongside at least
one numeric column being populated.

CONTINUATION signal: Text appears only in the item_description column; ALL numeric
columns (quantity, unit_price, amount) are blank for that row -> append to
'description_detailed'. Do NOT create a new line item.

PAGE FOOTER IMMUNITY: Lines such as "Page No. X of Y CREDIT NOTE Original Copy" and
"Credit Note Created by www.mazu.in" are document footers. NEVER treat them as line
items or continuation rows. Skip them entirely.

NO SERIAL NUMBER documents: When there is no sno column, rely entirely on
quantity + unit_price/amount values appearing together in the same row to identify
a new item.

SUNDRY / FOOTER BOUNDARY:
The item table ends when rows shift to a two-column label-value pattern. Detect using:
- Labels matching: CGST, SGST, IGST, Cess, Tax, Tax Amount, Total Tax, Rounded Off,
  Round Off, Sub Total, Grand Total, Total, Taxable Value, Taxable Amount,
  Amount in Words, Net Payable, Amount Payable, Net Value, Discount (in summary
  position), Freight, Forwarding, TCS, TDS, TDS/TCS.
- Rows with a value in the rightmost column but no quantity or unit_price columns
  populated.
- A "Sundry Details", "Bill Sundry", or "Other Charges" section header line.
- An inline tax summary string containing patterns like "Credit Note @X% = ...,
  CGST = ..., SGST = ..." or pipe-separated ( | ) key=value pairs.
Once this boundary is detected, stop creating line item objects. All subsequent
rows are sundry / footer / other-charges data.


## OTHER CHARGES

'other_charges' is an ARRAY of {description, amount} pairs capturing line-level extra

Common Indian examples: Loading Charges, Unloading Charges, Packing Charges,
Forwarding Charges, Labour Charges, Handling Charges, Insurance, Octroi.

Do NOT include in 'other_charges':
  - CGST, SGST, IGST, Cess, Tax Amount, Total Tax (these belong in tax_summary /

  - Round Off / Rounded Off (belongs in sundry_details.rounded_off_*).
  - Document-level Discount (belongs in sundry_details.discount).
  - Freight & Forwarding Charges if the document has a dedicated
    'sundry_details.freight_forwarding_charges' line — pick the sundry slot only.
  - Sub Total / Grand Total / Total / Amount in Words.

If no such charges exist, output 'other_charges' as an empty array [].


## TAX SUMMARY RULES

'tax_summary' must ONLY be populated from a visually distinct, multi-column TABLE
that appears between the item section and the footer, with explicit column headers
such as: Tax Rate, Taxable Amount / Value, CGST, SGST, IGST.

The following are NOT a tax summary table and must NOT be used to populate
'tax_summary':

    "Credit Note @2% = 2047.08, CGST = 20.46, SGST = 20.46 | Credit Note @4% = ..."

If no structured tax summary TABLE exists, output 'tax_summary' as an empty array
[]. Do NOT fabricate tax_summary rows from any inline text, footer strings, or
prose summaries regardless of how clearly the values are stated.

When a proper table DOES exist, extract as an ARRAY of objects — one per slab row:

PASS 2 — VALIDATION (run on your own Pass 1 output before responding)
========================================

1. LINE ITEMS — NULL TO ZERO
For every numeric field in line_items (quantity, unit_price, amount) that is null
when a number was clearly expected (column header exists but cell was blank or
unreadable), replace null with 0.

2. ITEM_DESCRIPTION FIELD PROTECTION
'item_description' must never be null or empty. If truly unreadable, use
"Unknown Item". Apply the CONTINUATION rule strictly — trailing description-only
rows must be merged into the previous item's 'description_detailed', never promoted
to a new item object. If 'description_detailed' would contain only an HSN code or a
quantity+unit string, correct it to null.

3. HSN_SAC VERIFICATION (with quantity recovery)
Review every item in line_items.
3.1  If any 'hsn_sac' value looks like a quantity value rather than an HSN code,
     correct 'hsn_sac' to null. Suspicious patterns:
       - A small decimal such as "2.00", "3.00", "4.00", "5.00", "10.00" — almost
         always quantities, not HSN codes.
       - A value that matches the sno or the printed quantity of that same row.
     A genuine HSN/SAC code is typically a 2/4/6/8-digit integer string with no
     decimal point (e.g., "05", "07", "8471", "09011010").
3.2  RECOVERY: After step 3.1, if 'quantity' for that same row is 0 or null, set
     'quantity' to the numeric value of the string just removed from 'hsn_sac'.
     This restores the value shifted out of the QTY column.
3.3  A valid HSN/SAC code comes exclusively from the cell under the HSN/SAC header
     — never from qty, sno, or description columns.
3.4  HSN CORRECTION MUST NOT TOUCH OTHER COLUMNS: When correcting 'hsn_sac' or
     recovering 'quantity', do NOT modify 'unit_price', 'disc', 'tax_percent',
     'amount', 'unit', or any other field.

4. TAX_PERCENT VERIFICATION
